# ADR 0001. Модульный монолит с пакетами по фичам

- Статус: принято
- Дата: 31.10.2026

## Контекст

billing-hub — учебный B2B-биллинг. Нужна структура, которая: делает границы предметных областей явными в коде, не требует распределённой инфраструктуры до M5, и не даёт модулям ходить в чужие таблицы.

## Решение

- Один исполняемый сервис `billing-service` с пакетами по фичам: `customers`, `contracts`, `invoicing`, `payments`, `penalties`, `dunning`, `reporting`, `integration`, `shared`.
- Внутри модуля: `api` (публичный интерфейс и DTO), `web` (контроллеры), `domain` (сущности и чистая логика), `app` (сервисы и маппинг), `infra` (репозитории).
- Модуль обращается к другому модулю только через его `api` (например, `customers.api.CustomerDirectory`) или через события. Прямой доступ к чужим репозиториям и сущностям запрещён. Ссылки между модулями — по id (`contract.customer_id`), без связей JPA.

## Почему так

- Границы видны в коде и в структуре пакетов, но сервис один: одна транзакция, одна база, нет сетевых сбоев между модулями.
- Пакеты по фичам, а не по слоям: изменение одной фичи трогает один каталог.
- Переход к отдельным сервисам возможен позже: `api`-интерфейсы уже задают контракт.

## Что будет проверять

- ArchUnit-тест на запрет импортов чужих `infra` и `domain` — добавляется отдельным шагом, пока не сделан. До его появления правило держится на ревью.

## Последствия

- Тесты интеграции поднимают весь сервис. Медленнее, чем изолированные модули, но ближе к продовому поведению.
- Модули `invoicing`, `payments` и остальные пока пустые: появятся на своих этапах.

## Обновление

Дата: 07.11.2026. Решение не менялось, добавлено состояние на эту дату.

- Реализованы модули `customers`, `contracts`, `invoicing` и пакет `shared`. Модули `payments`, `penalties`, `dunning`, `reporting`, `integration` запланированы, но не созданы.
- Границу между модулями проверяет ArchUnit-тест `ModuleBoundaryTest`. Раньше в этом разделе было написано, что проверка только на ревью и тест запланирован; это больше не так.
- Пакет `demo` (генератор данных для профиля `demo`) не входит в схему модулей.
