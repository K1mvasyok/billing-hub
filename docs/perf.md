# Performance notes

Single measurement on a local machine (Windows 11, Docker Desktop, PostgreSQL 17 in a container). The numbers are for the demo dataset below. They are not a load test and not a benchmark of the hardware.

## Dataset

Generated by the `demo` profile (`DemoDataGenerator`, Datafaker with a fixed seed):

| Entity | Count |
|---|---|
| Customers | 10 000 |
| Plans (with two prices each; price changes on 1 July 2026) | 5 |
| Contracts (ACTIVE, 2026) | 15 000 |
| Contract items | about 1–2 per contract, 30% start at a random day of 2026 |
| Billing runs (2026-01 … 2026-12) | 12 |
| Invoices after all runs | 164 679, all in status `ISSUED`, 51 MB table |

Data generation took 1 min 7 s.

Total for the year: about 22 min 37 s. The created counts add up to 164 679, the same as the invoice table.

Skipped contracts have no lines in that month, because their items start later in 2026. That is correct behaviour, not an error.

Observations:
- Time per month grows from about 1.3 min to about 2 min as more invoices exist. Each run also takes longer when more contracts produce invoices, since the skip path does less work.
- December took 3 min 53 s with the same number of created invoices as November (2 min 01 s). This is a single run, so I cannot separate the cause (table size, a background process, or noise). Repeat runs are needed before drawing a conclusion.

## Query plans

### Overdue invoices, all customers

```sql
select id, number, customer_id, due_date, total, paid
from invoice
where status in ('ISSUED', 'PARTIALLY_PAID') and due_date < date '2026-03-01'
order by customer_id, due_date;
```

- With `ix_invoice_customer_due`: sequential scan, 21.4 ms, 12 047 rows.
- Without the index (dropped inside a rolled-back transaction): sequential scan, 21.3 ms.

**Finding:** the index does not help this query. Its leading column is `customer_id`, and the query filters on `due_date` alone. A global overdue list needs an index that starts with `due_date`, for example a partial index `(due_date) where status in ('ISSUED', 'PARTIALLY_PAID')`. This is not added yet: it is a schema change that needs a new changeset and a decision about which queries matter.

### Overdue invoices for one customer

```sql
select id, number, due_date, total, paid
from invoice
where customer_id = '<customer>' and status in ('ISSUED', 'PARTIALLY_PAID') and due_date < date '2027-01-15'
order by due_date;
```

- With `ix_invoice_customer_due`: bitmap index scan, 88 rows, 0.48 ms.

The index works for the query it was designed for.
